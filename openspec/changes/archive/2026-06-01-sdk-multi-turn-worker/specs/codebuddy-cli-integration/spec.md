## MODIFIED Requirements

### Requirement: Multi-turn continuation via explicit session id

When `worker.kind === 'ssh'` the system SHALL preserve conversation context across continuation turns within one worker lifetime by using the CodeBuddy CLI `--session-id` and `--resume` flags, so that Symphony §7.1 continuation semantics ("continuation turns SHOULD send only continuation guidance to the existing thread") are satisfied under SSH's per-turn-subprocess model.

When `worker.kind === 'local'` the system SHALL NOT use this CLI flag path; the local mode is governed by the `sdk-multi-turn-worker` capability and uses the SDK session API instead.

Implementation note (SSH-only deviation from Symphony §10.3): under SSH, CodeBuddy CLI exits after each `--print` invocation rather than keeping the subprocess alive across turns. The SSH path MUST therefore spawn a new subprocess per turn and rely on the CLI's persistent session store (`~/.codebuddy/projects/<sanitized-cwd>/sessions/`) for context. The `-c/--continue` flag MUST NOT be used (it resumes the most-recent session globally, which causes cross-talk under concurrency); `-r <session_id>` is the only correct resume mechanism.

#### Scenario: First turn establishes session (SSH only)

- **WHEN** the runner starts turn 1 for a new issue and `worker.kind === 'ssh'`
- **THEN** the CLI is invoked with `--session-id <uuid>` where `<uuid>` is generated by the orchestrator
- **AND** the full rendered task prompt is passed as the positional argument
- **AND** the generated `<uuid>` is recorded as `agent_session_id` in the LiveSession state

#### Scenario: Continuation turn resumes by id (SSH only)

- **WHEN** turn N completes successfully and `worker.kind === 'ssh'` and the tracker issue state is still active
- **AND** turn count is below `agent.max_turns`
- **THEN** turn N+1 is invoked with `--resume <agent_session_id>` reusing the same id from turn 1
- **AND** only continuation guidance is sent; the full task prompt is NOT resent

#### Scenario: Concurrent tasks never share session id (SSH only)

- **WHEN** two issues are dispatched concurrently and both run under `worker.kind === 'ssh'`
- **THEN** each receives a distinct `agent_session_id`
- **AND** `-c/--continue` is never used by any invocation (only `-r <id>` is used)

#### Scenario: Local mode does NOT use the CLI flag path

- **WHEN** `worker.kind === 'local'`
- **THEN** the local SDK runner does NOT invoke the CodeBuddy CLI with `--session-id` or `--resume`
- **AND** continuation across turns is provided by the long-lived `Session` (see `sdk-multi-turn-worker` capability)
